## The build

1. **The seam.** A `ThreadPass` interface (`ribbon/thread_pass.ts`:
   `build`, `extrude`, `collapse`, `tuck`, `fills` optional) that
   `StripPass` implements unchanged; the façade holds the pass by
   interface. `rp` is read once at construction (a `?rp=sdf`
   key=value link key and a module override for probes; NOT a codec
   param — the codec decision comes with G3-3's default flip).
2. **`ribbon/ribbon_sdf.ts`.** The SDF pass: per-segment quads over
   the SAMP centreline (3.2's footprint: bisector trapezoids on smooth
   segments, capsule boxes at folds and open ends), fold detection in
   `update()`'s write (O(N), 3.2's rule: ρ < 1.2·(h·maxWMul + pad),
   ±W split, W_max = 2 ctrl, under kinkSep), and the fragment program
   of 3.3 (`sdCone` own/±1 min, `gapKeepAt`, the G2 paint library via
   the same `compose` text the strip runs, `withExplore`'s anchor
   port — `paint_explore.test.ts` pins both hosts).
   - The varying budget is 3.3's open question: ~13-14 of 15
     guaranteed vec4s. The fallback (fragment fetches KSTATIC/KGEOM
     itself) is chosen by a `MAX_VARYING_VECTORS` query at build, not
     by device name; the choice is probe-visible (`__knotRenderer()`).
   - `collapse` (the pluck light path): the SDF has no mesh to
     re-extrude — it writes RADII (3's `setCollapse writes radii`),
     which `extrude` already does through `g3WriteRadii`; `tuck`
     writes the SAMP rows the tuck clamps (the same samples write).
3. **The A/B.** `rp=sdf` vs `rp=strip` on a fixed link set (knot
   default, a fat link, a fabric game, the daily, a reveal link, an
   explore link): attributed pixel diffs (the G3-1 pattern:
   `.claude/probes/K8/G3-2/`), the shader status line clean, frame
   times by `scripts/bench_frame.mjs`. Levi's phone check gates
   G3-3, not this stage; nothing flips a default here.

## Status (2026-10-21)

Build step 1 (the seam) landed in `957ba833`: `ribbon/thread_pass.ts`
(the interface), `StripPass implements ThreadPass`, `RibbonStyle.rp`,
and scene.ts reading `?rp=sdf` off the link at rebuild. Until
`ribbon_sdf.ts` exists, `rp=sdf` constructs the strip and sets the
renderer-internal `rpFallback` flag, so an A/B can never mistake the
two. Steps 2-3 (the SDF pass and the A/B) are the remaining build —
start from `ribbon/strip_pass.ts`'s call shapes and
`src/render/fabric_sdf.ts` (`sampAt`, `fabricUniforms`); the G3
tables (SAMP/RADII/CHAIN/RANGES) are already written every frame by
`update()` and `g3WriteChain`.

## Status (2026-10-22, steps 2–3 built, K816)

`ribbon/ribbon_sdf.ts` landed: per-segment quads (attribute-built,
not instanced; capsule boxes on every segment — no bisector
trapezoids or fold pinch yet, and no joint-cluster discard: both are
recorded deviations for a follow-up stage), the fragment of 3.3
(`sdCone` own/±1 min, `aaCov`, `gapKeepAt` over the segment's RANGES
windows, the strip fragment's paint orchestration with the side from
the cone's lateral distance), `SdfPass implements ThreadPass` (no
fills; one scene mesh from `rootMesh()`), the registry entry
`ribbon-sdf` (wave 1 iff `?rp=sdf`), and warm-up context `sdf`. Two
build bugs found by probe and fixed on the way: a Shader's resources
accessor is fixed at construction (the G3 sources now ride
`sdfShader(g3)` creation), and RADII packs one float per sample
(`radAt` fixed in `fabric_sdf.ts`); the pass's `extrude` never
returns null (a null multiplier marks the chain radius-less).
Desktop A/B (`.claude/probes/K8/G3-2/`, real-time, `am=instant`):
no page errors, no shader warnings; pixel diffs vs `rp=strip`
(sampled region, mean |Δ| / %>32): knot 21.5 / 17.4%, fabric
10.1 / 10.0%, border 2.4 / 0.15% — attributed to the cone joins
reading thinner than the strip's overlapping bisector quads at
bends; section colors and the border look match. Not measured yet:
frame times (`scripts/bench_frame.mjs`), the explore variant (the
SDF program has no `withExplore` port yet — explore links under
`rp=sdf` draw threads unrevealed), a fat link, the daily, and any
phone check (G3-3's gate, not this stage's).
