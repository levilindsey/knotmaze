# K793: search the settings panel, and collapse or expand all

Ledger: K793. One stage, opus, 2 h cap. Levi, 2026-10-21: "We need a
search bar in the settings panel. It should use fuzzy search. It should
search the text of the param names, but we should also encode tags for

That is item 8 below.

## Goal

A search box at the top of the settings panel (`src/ui/tweakpane_panel.ts`;
on the phone, the sheet in `src/ui/panel_sheet.ts`). As the player types,
the panel shows only the rows that match, inside their folders, with those
folders open. Matching is fuzzy, over:
- each row's name;
- its tags: the words a player might use for it after forgetting its name
  (see item 3);
- at a lower weight, its folder's title and, for an enum row, its option
  labels, so "hunter" finds the minotaur row.

Clearing the box puts the panel back as it was, each folder's open or
closed state included.

## Design

These are recommendations. Change one only with a reason in the Handoff.

1. **A pure module**, `src/ui/panel_search.ts`. It builds an index from
   (row id, label, tags, folder path, options) and answers a query with the
   matching rows, their scores and the label's matched character ranges.
   No DOM and no Tweakpane, so `test/ui/panel_search.test.ts` runs in Node.
2. **The matcher.**
   - Typo-tolerant: one wrong, missing, extra or swapped letter in a word
     of 4+ letters still matches ("tempreature", "minotuar").
   - Prefixes match and rank high ("mino" finds Minotaur).
   - A query of several words matches a row only when every word matches
     something in it, in any order.
   - A name match ranks above a tag match, and a tag match above a folder
     or option match.
   - Deterministic.

   Compare a library (Fuse.js, uFuzzy, fuzzysort) with a small hand-rolled
   scorer, on a fixed list of 30+ queries kept in the test file. Pick the
   one with the best results and record the comparison in the Handoff. A
   library must pass the K122 notices check (`npm run build` fails on an
   unlicensed package) and add little to the bundle (under about 10 KB
   gzipped).
3. **The tags table**, `src/ui/param_tags.ts`. Every panel row gets 3-10
   lowercase words or short phrases. That means params, and also buttons
   such as the seed and share rows. The tags are:
   - synonyms and plainer words for the name ("monster", "bull" and
     "chaser" for the minotaur);
   - what the row changes, as a player sees it ("wiggle" and "jiggle" for
     temperature);
   - the link key itself (`tw`, `ky`), for players who know the URL.

   Write the tags from each param's code comments and what it does, not
   from its name alone. A test fails when a panel row has no tags, so every
   later param gets some. Name that rule in the lore.
4. **Filtering in place.**
   - Hide the rows that don't match, with Tweakpane v4's `hidden` on each
     blade. Hide folders with no match, and open folders with one.
   - Keep the panel's order; don't build a separate results list.
   - Mark the matched letters of a visible label, if Tweakpane's label DOM
     allows it without breaking anything.
   - For a row shown only because a tag matched, show that tag (a small
     "monster" hint, say), so the player sees why the row is there.
   - Search covers the rows the player can see in the current panel mode.
     It opens collapsed folders but doesn't reveal rows that a mode hides.
5. **The box.**
   - It filters live on every keystroke. Use a plain DOM input above the
     pane, not a Tweakpane text binding, which commits only on blur or
     Enter. It stays visible (sticky) while the results scroll.
   - A clear button (×). Escape clears the box; a second Escape leaves it.
   - Enter moves the focus to the best match's control and scrolls it into
     view.
   - "No settings match" when nothing does.
   - Accessibility: `type="search"`, `aria-label="Search settings"`, and a
     polite live region that gives the count.
6. **What search must never do.**
   - Change a param, the link or the maze, or count as a panel edit. The
     daily's rule that a panel edit makes it an ordinary design
     (`daily_link.ts`) must not trip.
   - Reach the game's keys. Typing "w", the arrows, or L and N in the box
     must not move the player or fire a key action. Check that the guards
     in `key_moves.ts` and the other window key listeners cover a text
     input, and add one if they don't.
   - Go into the link. Whether the query survives closing the panel is
     your call; my recommendation is that it does, until a reload.
7. **The locks agent's rows.** The K138 agent's branch adds `keys` (`ky`)
   and `lockMode` (`lkm`), with panel rows. It will likely merge to master
   before you finish. Before you stop, rebase onto master, and give those
   rows tags if they're there.

   Keep your per-row changes small, so that its later slices (new `lkm`
   options) and your branch rebase cleanly. Build the index by walking the
   pane's blades after the panel is built, rather than by editing each
   row's code.

   K795 (opus, beside you) adds panel rows too: the beat rider's, rows
   for params that have none, and new params. Whichever of you merges
   second tags the other's rows. If its rows are on master when you
   rebase, tag them.
8. **Collapse all and expand all.** Two small buttons beside the search
   box, with tooltips and aria labels. They act on every folder, nested
   ones included. During a search they act on the folders the search
   shows, and clearing the search keeps what the player chose. Where the
   panel already saves folder states, follow that.

**Where the build differs from the design, and why.**
- **Item 4, hiding.** The search hides rows with its own class,
  `kp-sx-out` (display:none !important), not with the blades' `hidden`.
  refreshCond owns `hidden` for a mode's rows and rewrites it after every
  change, so the two would overwrite each other, and a clear could reveal
  a row that a mode hides. A row under `.tp-v-hidden` never shows, and
  refreshCond calls `searchUi.refresh()`.
- **Item 5, Enter.**
  - On desktop it works as designed: it focuses the best match's control
    and scrolls it into view.
  - On a coarse pointer it releases the box instead and outlines the row
    for 1.2 s (`kp-sx-hit`). Focusing the row's text field would keep the
    soft keyboard up over the panel.
- **Item 6.**
  - The query survives a panel close and is gone after a reload, as the
    brief recommended.
  - No new key guard was needed. `keyBelongsElsewhere`
    (`src/app/input_keys.ts`) already skips keys typed in an input or in
    the panel.
  - The probe checks that wasd and the arrows typed in the box move
    nothing. As a control, it checks that the arrows pressed on the page
    do move the head.
- **Item 7.**
  - The index walks the pane's blades after the panel is built, so the
    rows carry no search code.
  - One per-row change: the Daily button's title becomes "Daily #N" at
    runtime, so it carries `data-kp-id="btn:Daily"`, and `setDailyLabel`
    calls `relabel()`.
- **The matcher's weights:** label 1, tag 0.6, link key 0.6, option 0.3,
  folder 0.25. A word prefix ranks above a substring, and ties go by
  panel order.
- **The typo rule.** A one-edit match (a wrong, missing, extra or swapped
  letter) counts only for a query word of 4+ letters that has no exact
  match anywhere in the index. So a correctly spelled word does not
  also pull in rows that are one letter away from it.

**Library comparison: not run, the one unmet item.** Fuse.js, uFuzzy and
fuzzysort are not installed, and none of them was run on the 44 queries.
I chose the hand-rolled matcher from their documented behaviour:
- **fuzzysort** matches subsequences, so a wrong or swapped letter fails
  ("minotuar" is not a subsequence of "minotaur"). It cannot pass the
  brief's typo rule.
- **Fuse.js** tolerates typos (Bitap with a score threshold) and has
  per-key weights. But it scores by distance from the start of the whole
  field, not from the start of a word, and an AND of several words needs
  its extended-search syntax. A threshold that admits "tempreature"
  without adding noise to short words is the hard part.
- **uFuzzy** comes closest: it ANDs the terms and has a single-error
  mode. But it ranks by its own rules, so getting name > tag > option >
  folder would take one search per field and a merge.
- **The hand-rolled matcher** is 302 lines, with no dependency and no
  notices entry. It encodes the four ranking rules directly and passes
  all 44 queries.
