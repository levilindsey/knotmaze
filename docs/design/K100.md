# K100: the fog of war resets on a restart only (one stage)

Levi, 2026-10-13: "The fog should reset when the maze restarts. But the
fog shouldn't reset if we just backtrack to the start."

## What happens today

- `FabricMazeRenderer.update()` (`src/render/fabric_maze_renderer.ts`,
  the block commented "Reset path: the fog's explored memory starts over
  too") clears `fogStamps` whenever `controller.pathEdges` is empty. So
  walking back to the entrance by hand, a daily's Reset path (a
  backtrack: `FabricMazeController.retreatToStart`, K47; see
  `resetPathAction` in `src/game/daily_attempt.ts`) and a real restart
  all clear the fog alike.
- `exploredRuns()` (`src/game/daily_attempt.ts`) mirrors that rule for a
  saved attempt: the runs crossed since the path was last empty. main.ts
  hands them to `fabric.restoreExplored(...)` when a saved daily attempt
  comes back (`pendingExplored`).
- K80's catch (`FabricMazeController.respawn()`) empties the path but
  keeps the taps, and its lore says the explored fog stays. Find what
  keeps it today and keep that behavior.

## Goal

- The fog's explored memory resets only when the solve restarts: a
  `FabricMazeController.reset()` (Reset path where `resetPathAction`
  says "restart", Play again, a rebuild or a new design, K80's Reset
  path) and nothing else. A backtrack to the entrance, by hand or by a
  daily's Reset path, keeps it, and so does a K80 catch.
- A suggestion, not a requirement: `reset()` empties `taps` and nothing
  else does, so the explored runs could become every tap since the
  restart (`c.taps`), and the renderer could key its reset on the solve
  restarting instead of on the path emptying. Pick the cleanest signal
  and say why.
- K47's saves and replays must agree with live play: an attempt restored
  after a backtrack to the entrance shows the fog the live page showed
  before the reload.
- Memory-trail mode (no backtracks) and fog off behave as before.
