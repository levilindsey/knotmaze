## Stage 1 design (2026-10-14 16:40)

**The profile texels.** Three texels at the end of every slot row:
GAP_PROF_BASE 111, so GAP_TEX_W 111 -> 114. Master's GLSL never reads
them.
- P0 and P1, one per ramp: `[aS, F, dK, tK]`.
  - aS: the over-chain arc where the solid part ends, in the slot
    polyline's frame. The frame is
    `a(c) = overCenter + U(c) - U(overCtrl)`, where U is the unwrapped
    arc map: rings add the total per lap, and open chains clamp.
  - F: the fade's SIGNED arc length (aE - aS). Its sign says which side
    is hidden. A hard end stores +-1e-6, a step.
  - (dK, tK): one interior knot of the ramp. The thread's fade is linear
    in CTRL, so in arc it is piecewise linear, with knots at integer
    ctrls. dK is the knot's share of the fade's arc and tK its share of
    the fade. No knot: (1, 1). A fade of at most 1 ctrl (the default
    fade is 1, FADE_MIN 0.35) has at most one interior knot, so the
    ramp is exact. With more, the knot nearest the middle is kept and
    the slot counts as approximate.
- P2: `[solved strength, flags, 0, 0]`. The flags are bits: 1 ramp 0
  present, 2 ramp 1 present, 4 ramp 0 is a frontier (the end look
  applies), 8 ramp 1 is a frontier, 16 combine by max.

**The gate bit is in texel 3.w, not 8.w.** It is bit 4 of the slot's
flags (1 perp, 2 self). The brief named 8.w. 3.w is fetched before the
search in every program, and 8.w only after it, so the explore program
pays no extra fetch for a slot that isn't shaped. Master's code tests
bits 1 and 2 only. 8.w stays free.

**How a piece's ends become ramps.** One piece with both ends in the
footprint: two ramps, combined by MIN (a point lies in at most one of
the fades). Two pieces with one end each in the footprint: combined by
MAX, ties preferring the solid one (kExploreAt's best-of rule). A ramp
evaluates as follows:
- `d = (A - aS) / F`; d <= 0 is solid (v 1, no look).
- Otherwise t is the piecewise-linear map through (dK, tK), clamped to
  1, and `v = 1 - smoothstep(t)`.
- u = t on a frontier, else -1. At t >= 1 the ramp is hidden (v 0, no
  look), as kExploreAt's `v == best && u < 0` rule gives at the fade's
  end.
- s = |A - aS| is the world arc from the solid end, which is exactly
  what the look reads (`kArcU(kExX) - kArcU(kExSolid)`).

**The shared look.** The thread's main and the cut call one function in
`explore_glsl.ts`:

`highp float kExploreLook(int look, highp float v, highp float u,
highp float s, highp float lat, highp float sideFw, highp float pxW)`

- lat is `vUV.y - 0.5`, 0 on the centerline.
- It returns the look's coverage, or v for the fade and halo looks and
  outside a frontier.
- The glow look's tint stays in the thread's main. It colors the
  thread; it is not coverage.

`exploreCutCover(int row, highp float A, highp float pxW)` reads the
profile and calls it with lat 0 and `sideFw = pxW / threadWidth`.

**The shaped cut.** It lives in the explore ribbon program only, through
two more exact-once anchors in GAP_FRAG_LIB's gapKeepAt. The
declarations move to just before `highp float gapKeepAt(`, where the
paint library and kSmooth are already declared.
- After the `sure2` line: a ribbon slot (full, not a fan) with the gate
  bit and the mode on sets `sure2 = 0`. The search then finds the true
  nearest segment, with no early stop inside the silhouette, which
  could otherwise misplace the projection by up to the half-width. The
  early-sure branch is skipped too. The full path gives the same value
  inside the silhouette (k = 0, fs = 1).
- After `if (bk < 0) continue;`, it computes
  `A = polyStart + min(bk + bt, kLast) * polyStep` (texel 4, the formula
  self-exclusion already uses) and
  `gst = gapStrength(P2.x) * exploreCutCover(row, A, pxW)`. When gst is
  0 the slot is skipped.

**The CPU side.**
- The classifier runs in `applyExploreGaps`, on every declaration change
  and after every solve, for live crossing slots while the mode is on.
- The footprint is the polyline's arc range: polyStart to polyStart +
  (n - 1) polyStep.
  - A whole chain is solid. A chain with no piece is hidden.
  - For each piece, take its copy nearest the over pass (rings) and skip
    it if its extent misses the range.
  - A piece whose solid part covers the range makes the slot solid.
  - An end matters when it lies inside the range. An open chain's
    terminal never matters.
  - No end that matters: hidden. Up to two ends: shaped. More than two:
    2b's scalar, counted as a fallback.
- Hidden and solid slots take 2b's path exactly (`setVis` 0 and 1).
- A shaped slot keeps its solved reject radii, so it is never rejected.
  Its texel 1.w gets 2b's scalar (0 when the over pass is hidden), so
  the fans and the still pluck see exactly 2b's gate. Stage 2 shapes
  them. P2.x keeps the solved strength for the shaped cut.
- `setShape` keys each slot's profile and skips unchanged writes.
  noteSolved resets it with the factor.

**Row-partial upload.** The gap texture becomes a row-dirty source with
its own uploader, `knot-gap-rows`, registered at module load as
float_rows' is. Every write marks its row. `upload()` sends each dirty
run with texSubImage2D, or nothing when the table is clean.
`GAP_UPLOAD_STATS` counts the bytes and calls.

**Calls.**
- Draw order: accepted within the fade. The cut is the geometric cut
  times the coverage everywhere, the proof's ideal. Inside the silhouette
  a partial cut shows whichever thread the base layer drew first, as
  2b's fading factor and the intro ramp already do. The alternative, a
  total silhouette above vis 0.5 with only the casing fading, is for
  Levi.
- The look at the projection uses the centerline (lat 0). The dots and
  beacon looks cut a casing per dot. Fray cuts by its center fiber,
  which wanders off the centerline, so its cut flickers along the
  fiber's sine.
- The fans and the still pluck keep 2b's scalar (stage 2).
- underWindows and the 0.5 rule for `slotExploreHid` stay binary, as in
  2b (stage 2).
