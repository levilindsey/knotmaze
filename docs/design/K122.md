### Research

How others do it (sources in `research_notes.md`): Chrome builds
`chrome://credits` at build time from each third_party dir's
`README.chromium` (`tools/licenses.py credits`), and `licenses.py scan`
"complain[s] about incomplete or missing data"; Android's
`oss-licenses-plugin` reads the POMs at build time and generates the "Open
source licenses" screen ("you as a developer are responsible for
appropriately displaying the notices");
Flutter's tool collects every package's LICENSE into one NOTICES asset that
`LicensePage` shows; VS Code ships one `ThirdPartyNotices.txt` (name,
version, URL, full text, repeated per package). Bundlers keep `/*! */` and
`@license` comments inline (esbuild `eof`) or move them to a `.LICENSE.txt`
beside the file (terser-webpack-plugin, esbuild `linked`). The licenses
need the notice to travel with copies; BSD-3 lets binary redistribution do it
"in the documentation and/or other materials provided with the distribution",
which a page served with the app arguably is (a lawyer's call, not mine).

Measured here: the default Vite 8 build keeps 0 legal comments (confirmed);
asking for them (`output.comments.legal`) keeps exactly one, Tweakpane's
one-line banner, which is not the permission notice. The other seven
packages hold their license only in a LICENSE file (two hold none), so a
comments-only route cannot work and a page is the real carrier. Pages
redirects `/licenses.html` to `/licenses` (live check on this site's
`/404.html`: `308 Location: /404`, and through the levi.dev proxy
`https://levi.dev/knotmaze/404`, which the proxy's own header describes);
the page uses only relative links, so it reads the same at both hosts.

### Tooling choice

Vite 8.1.5 has `build.license` (writes `.vite/license.md`, or `.json`). Run
on this repo it listed the 8 packages, two of them (tweakpane,
@pixi/colord) with EMPTY text (Markdown at a hidden path by default); it
reads the first license file only, walks every module a chunk lists (not
only those that render code; no difference in this bundle today), and
cannot fail the build. So: a small plugin of our own (about 500 lines of
code with the page renderer), driven by `chunk.modules` (renderedLength >
0), with the policy, fallbacks and credits in one tracked file.
`rollup-plugin-license` (not run; its README describes a bundle-based list
that skips tree-shaken packages, an `allow` list and `failOnViolation`)
would add a dependency for logic we must own anyway (fallbacks, the page,
the Hershey rule). Vite's and Rolldown's own virtual helper modules (about
4.8 KB: preload helper, modulepreload polyfill, module runtime) are
treated as build tooling, as Vite's `build.license` does; any other virtual
module with code fails the build.
