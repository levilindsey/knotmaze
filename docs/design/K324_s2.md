## What to build

1. **The plumbing.**
   - The frame passes `params.minoTelegraph ? chase.plan(reach) : null`
     for the real-time chase, with reach = `minoTelegraphRuns`.
   - The renderer draws it with K525's route:
     - the lead partial run, from the minotaur's spot;
     - the whole runs after it;
     - the ring, only when `dest >= 0`.
   - Alphas:
     - the first run, lead included, at the look's alpha; the rest at
       half;
     - faint (about 0.45) while it roams, bright while it hunts;
     - in its lair, nothing until the last 0.5 s of its wait, then the
       exit tail's run (2.1's table).
   - `plan()` may not cover the lair's tail. If it doesn't, add it to
     `plan()` without moving any digest.
   - All three of `mtl`'s looks must work in real time.
2. **The moving end (K654).**
   - The problem: a changed `lead` changes `teleItemKey` and rewrites
     KPAINT, so a moving minotaur would rewrite the paint texture every
     frame.
   - The fix: ride the lead's moving end on a uniform, as the hover
     point does (`uKReach.w`). KPAINT keeps the route's fixed pieces,
     and the TELE branch clamps the lead piece's moving end to the
     uniform.
   - Keep the CPU mirror (`paint_math.ts`) line for line with the GLSL,
     with tests.
3. **Hidden thread (K652, K271).** Under K76's thread reveal, the line
   look draws over unrevealed threads; the rims already draw nothing
   there.
   - Fix it for both clocks if the fix stays in the telegraph's own
     drawing. For example, clip the line's pieces by
     `src/game/explore_view.ts`'s visible pieces.
   - If it needs `syncExplore` or the explore shader's visibility items
     (K139's), write it up and skip this step.
4. **Flicker.** While it hunts, the next run is live.
   - Count how often it changes, per second, while you walk.
   - Add hysteresis only if the count shows flicker at ties: keep the
     previous next run unless the new one is shorter by the turn-back
     margin (`maybeReverse`'s rule).
