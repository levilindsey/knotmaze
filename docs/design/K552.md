# K552 brief: the daily's title thread becomes a flag, off by default

Ledger item K552. Levi, 2026-10-19: "I don't actually want dailies to
have a title thread. BUT, I like the idea of supporting a flag to
conditionally render them with the title thread. But it should default
to off, AND, if feasible, I'd like for the rest of the maze topography
to be the same with or without the title thread. Unless that's too
difficult, then don't worry about it."

One Opus agent, one stage. Decisions this brief makes are marked
(picked). The open ones are Calls for Levi at the end, each with a
recommendation: build the recommendation unless Levi says otherwise
before the stage starts.

## Where things stand (master 71ee949)

- K115 stage 3a (6625160) threads every daily's name. `dailyTitle(n)` =
  `` `Daily #${n}` `` (`src/ui/daily_link.ts:65`) is fed at two sites:
  - `src/main.ts:211`, the worker prebuild:
    `title: launch.daily !== null ? dailyTitle(launch.daily) : ""`;
  - `src/main.ts:413`, `SceneDeps.dailyTitle`, read on every rebuild at
    `src/app/scene.ts:235`.
- `buildSceneGraph` hangs the title AFTER the plan, the cuts and the
  untitled walk's start/exit selection (`src/core/scene_graph.ts:175-196`).
  - `attachTitle` (`src/core/text_graph.ts:1458`) takes its seam from
    `walk0.start` (:1470).
  - The titled walk is built with `start: "mentr_a"`,
    `exit: walk0.exit` and `mazeStart: seam`.
  - Title `""` runs none of it, so the build is byte-identical to an
    untitled one.
- **The maze's combinatorics are therefore already independent of the
  title, by construction:** same plan, same cuts, same walk0.
- **What the title adds:**
  - the word's strands and the connector into the seam;
  - the title edges in the walk (appended, so maze edge indices stay
    stable: `titleEdges` and `titleLength`, `src/core/walk_graph.ts:259-296`);
  - a solve clock that starts at the first arrival at `mazeStart`
    (`src/main.ts:1281-1286`);
  - title taps, which add nothing to the stats
    (`src/game/fabric_controller.ts:233`).
- **What the title still changes (this stage's work):**
  1. **K47's fingerprint.** `walkFingerprint`
     (`src/game/daily_attempt.ts:19`) hashes every walk edge, title
     edges included, and an attempt's taps include the title taps. A
     flag toggle mid-attempt therefore refuses the saved attempt
     (`restoreAttempt` returns `"maze"`); `src/main.ts:1228-1256` warns,
     and the next save overwrites the record, so the attempt is lost.
  2. **The move log keeps title taps.** Stage 3's call C4 put leading
     `g` squares in the share grid (`docs/design/K115_stage3.md`), so
     two players' grids for one daily would differ by flag.
  3. **Layout, not topology.** The band sits `TITLE_GAP` (2 LU) above
     the maze top, and the viewport fits it. The pinned word's repulsion
     reaches the maze's top threads, so the relaxed geometry near the
     band may differ.

## Attempts and results survive a toggle (picked; Call C1)

A flag toggle must never lose an attempt or change a result. The picked
mechanism, Call C1's recommendation, is to store attempts in MAZE FORM.

- **The fingerprint covers the maze portion only.**
  - `walkFingerprint` skips `titleEdges` and uses `mazeStart ?? start`,
    so titled and untitled fingerprints agree.
  - An untitled walk's fingerprint stays byte-identical to today's (for
    it, the maze portion IS the walk), so saved untitled attempts keep
    restoring. Pin that in a test.
- **Save and restore.**
  - `attemptRecord` strips title taps and title path edges before
    saving.
  - On a titled scene, `restoreAttempt` replays the title's forced walk
    first (the shortest walk from start to `mazeStart`: the taps the
    player must make anyway), then the saved maze taps.
  - On an untitled scene it replays the saved taps as they are.
- **Stats, stars and results** are already maze-only. Prove it by test:
  one scripted solve of Daily #8, played titled and untitled, gives
  identical stats, stars, result record and share text.
- **The share grid** (Call C2's rec): drop title moves from the move
  log, or from the share rendering only (your choice; one home). This
  revises stage 3's C4. If Levi keeps C4, the test compares only the
  maze part of the share text.
- **Fallback.** Use it if the maze-form attempt proves unsound, e.g. if
  `replay` cannot take a title prefix plus maze taps.
  - Park a refused attempt instead of overwriting it: keep it under its
    fingerprint, so that toggling back restores it.
  - File the rest as a call.
