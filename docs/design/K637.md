# K637: why the minotaur sim's baseline rose

Ledger: K637. One stage, sonnet, 1 h cap. Probes only: no change to
`src/`, the tests, the docs or the lore.

## The question

- **Before.** On 2026-10-14, K80 turns stage 2 measured real time with
  K174's sim. That was between 86d404e and 02194b4; see
  `docs/design/K80_turns.md`, about line 695:
  - the greedy player: 1.66 catches a game at roamPull 0.5;
  - the fleers escaped 54-58% of hunts, and 75-77% with queued taps.
- **After.** At bcd907c, K324 stage 1 measured with its own copy of the
  harness (`.claude/probes/K324/rt/`); see `docs/design/K324_s1.md`,
  Handoff, "Baseline":
  - greedy: 2.50 catches, 6% of hunts escaped;
  - fleer: 0.86 catches, 50% escaped;
  - queued fleer: 0.51 catches, 75% escaped.
- **The candidates. Nobody has attributed the rise.**
  - **The harness.** K324's copy builds through `buildSceneGraph`
    (`src/core/scene_graph.ts`, added in 67c0604). The older copy built
    the plan by hand. The run protocol may differ too: seeds, reps,
    designs, pull and paces.
  - **The mazes.** K74 stage 3's trap-zone finish and H1's exit guard
    (9ccf360).
  - **The defaults.** K534 A1 (35f3ec2: gameMode, the Game folder, codec
    v7), and any other commit that moved a minotaur or generation
    default.
- **A trap (K639).** From 35f3ec2 on, the older harness copies (`rt_lib.ts`
  in K80's, K174's and K155's `rt/`) read the removed `deadEnds` switch, so
  they build mazes without dead ends. The older harness is valid only
  before 35f3ec2.

## Steps

1. **Protocol.** Find the exact run behind each number:
   - K80 turns stage 2's: its probes' `rt/results.md` (seeds, reps,
     designs, pull, players);
   - K324 stage 1's: its sweep in `rt_sweeps.ts`, the seeds and the reps.

   Then diff the two harness copies, `.claude/probes/K174/rt/` against
   `.claude/probes/K324/rt/`, above all `rt_sim.ts` (players, think times)
   and `rt_lib.ts` (maze build, params). Write the differences down.
2. **Harness check.** Pick one commit where both copies work: on or after
   67c0604 and before 35f3ec2. Run both copies there with one protocol.
   - The same numbers rule the harness out.
   - Different numbers: find which part of the copy causes them before
     you bisect.
3. **Endpoints.** With one protocol, measure the greedy player's catches
   at pull 0.5 at both ends: 02194b4 (or the commit K80 turns stage 2
   actually ran on) and bcd907c. This should reproduce 1.66 and 2.50
   within the noise. Give the noise: a second block of seeds, or the
   standard error.
4. **Bisect** between the endpoints along ancestry
   (`git merge-base --is-ancestor`, `git rev-list --first-parent`), not
   commit dates: the work-hours hook re-dates commits.
   - Check 9ccf360^ / 9ccf360 and 35f3ec2^ / 35f3ec2 first.
   - **Getting a commit's src.** Extract it with
     `git archive -o <tar> <sha> src` and `tar -xf <tar> -C <dir>`, into
     `.claude/probes/K637/src_<sha>/`. Point the harness at it with
     `KNOTMAZE_SRC=<dir>\src` (`rt_lib.ts` reads it). Node resolves
     packages by walking up to your worktree's `node_modules`.
   - **Which harness.** Use the older one before 35f3ec2 and K324's from
     35f3ec2 on, or one copy that works across the range, changing at
     most its imports.
5. **Attribute.** For each commit that moves the number by more than the
   noise, say:
   - which change in it does it: a default, a generation step or the
     chase;
   - whether that was intended, from its commit message, design doc or
     ledger item.

   Then recommend one of two things: accept it as the new baseline and
   update the documents, or file a fix.

## Constraints

- **Probes.** They go in `.claude/probes/K637/` in your worktree
  (untracked). Write `.claude/probes/K637/results.md` with a table: the
  commit, the harness, the protocol, the greedy player's catches at pull
  0.5, and the fleer's and the queued fleer's escapes.
- **Load.** The sim runs on fixed steps, so load does not change its
  results and it needs no perf lock. Still, other agents measure on this
  machine, so run at most 3 sim processes at a time.
- **Other files.** Read the main checkout's `.claude/probes/` and copy the
  harnesses out of it, but don't write there. Don't touch other agents'
  worktrees.

## Stop rule

comes first. Run `Get-Date` at the start and at each milestone.

A compaction is not a stop: after one, re-read this brief before going
on. Keep reads narrow (Grep -n, then Read with offset/limit).
