# K572 brief: attribute the phone's render regression

Ledger item K572. The round phone pass of 2026-10-20 (K156;
`docs/design/K156.md`, "Round 2026-10-20 handoff") found that the head
`d0406df` (app code `6fd8e70`) renders 1.5x to 3.7x slower on the Pixel 11
than the base `65a7787` (2026-10-16 01:34):

- **Render sync** (`renderLoop(60)`: a render plus a `readPixels`;
  median), head vs base:
  - knot gs24: 74.3 vs 20.2 ms. It is the same design, and the pixels
    are identical within tolerance 8.
  - dense: 64.3 vs 43.3 ms.
  - max-fabric: 93.9 vs 63.8 ms. Dense and max-fabric build different
    mazes on the two builds.
- **Frames at rest:** render sync is 8 to 16 ms higher, and the app's
  callback cost is about 2x.
- **Load** (K147): 40.7 vs 48.3 fps on the default link, 36.4 vs 51.7 at
  gs 18.
- **K568's confetti:** 44.9 vs 60 fps over its 8 s fall. Each confetti
  frame redraws the scene, so this may be the same regression rather
  than the confetti's own cost.

The 129 commits between the two builds include K8 G3-1 (`3465090`),
K320 stages 1, 2a and 2b, K553, K551, K268 and K76. This stage names the
commit or commits that cost it. **It is measurement only: change no app
code.**

## The work, in order

1. **Reproduce on the desktop first.**
   - Use the round's probe: `renderLoop(60)` in `k539_phone.mjs`, with
     the links in the round handoff's Step 6. The round folder is the
     main checkout's `.claude/probes/rounds/2026-10-20-d0406df/`. Read
     it, and copy what you need into your probes folder; never write
     there.
   - Conditions: headed Chrome on the real GPU, under the perf lock.
     Run at the phone's viewport (411x753 at dpr 2.625, by device
     emulation) and at the desktop's native size.
   - Measure base vs head on knot gs24, 3 reps each, alternating.
   - If the head is at least 1.5x the base on the desktop, bisect there
     (step 2). Otherwise bisect on the phone, with step 3's setup.
2. **Bisect** `65a7787..d0406df` on knot gs24's render sync.
   - Use `git bisect --first-parent`, and build each step with
     `pwsh scripts/preview.ps1 -Port <p> -Ref <commit>`.
   - A commit is bad when its median is past the midpoint between the
     base's and the head's.
   - Expect more than one contributor. After the first culprit, measure
     culprit^ vs culprit and culprit vs head. If the head is still at
     least 1.2x the culprit, bisect what remains.
   - Then measure the dense link at each culprit (culprit^ vs culprit,
     whose defaults should match).
3. **Confirm on the phone.**
   - For each culprit, run one A/B (culprit^ vs culprit) on knot gs24
     and dense, in ABBA order, logging the skin temperature for every
     cell.
   - The phone ran at 40 C at 11:01. Start below 37 C, and wait for it
     inside one blocking command.
   - Use the K156 kit (`scripts/phone_pass.ps1`; `docs/design/K156.md`)
     and the round's `p_common.mjs`. Check that nobody is using the
     phone first (K234), run the kit's idle wait, and run its cleanup at
     the end.
4. **K568's own cost, if the time allows.**
   - On the phone, run the confetti look (the round's Step 3, with
     `__knotConfetti`) at `6fd8e70^` vs `6fd8e70`, ABBA.
   - Both builds carry the same render code, so any difference is the
     confetti's own cost.

Steps 1-2 come before 3, and 3 before 4. Whatever is left goes in the
handoff for the next phone window.
