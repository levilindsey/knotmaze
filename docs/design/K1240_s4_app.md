# K1240 S4: the redesign in the app, behind a link flag

Ledgers: K1240 (the redesign), K1247 (its frame cost). One Claude Opus agent in its own worktree, on its
own branch from master. Cap 2 h.

## Why

Five days of the redesign live only in `.claude/probes/K1240/proto/`: the outline table (`outline.ts`),
the triangle fill fixed at structure (`fill_tri.ts`, K1277) and the per-pixel section paint (`paint.ts`,
`draw.ts`, K1278 stage 1). Measured against form B they beat the app's looks at crossings and in the fill,
but Levi has seen none of it on his phone, and the timing (about 21 ms a frame on def, desktop) has never
been taken on the Pixel. From this stage on, the redesign's work happens in `src/`.

## Goal

A link flag, `rp=outline` (the precedent is `rp=sdf`, K8), draws the threads from the redesign in the
app: the outline's borders and the triangle fill with the section paint, structure decided once per scene
and positions followed per frame, as in the prototype. Without the flag the app is unchanged.
- **Port, don't import.** The code moves into `src/` (for example `src/render/outline/`). Only the
  prototype's default path comes along: no `K16_*`/`K17_*` env switches, no debug hooks, no copies of
  master. Its output on the 12 scenes equals the prototype's default (check it once against the proto,
  then pin it in a test).
- **Where it builds** (main thread or the physics worker, K7) is yours to decide; say why, with numbers.
- Overlays the redesign doesn't draw yet (markers, trail, fog, reveal, pulses, gameplay paint) either
  keep working on top or are listed as missing. Knot mode and one maze link must work.

## Rules

- PowerShell. Read code through the shell (`Select-String`, ranges of `Get-Content`); the Read tool only
  right before an Edit. Junction `node_modules` from the main checkout; never `npm ci`.
- **Your files:** new files under `src/` for the redesign, the minimum wiring in `main.ts`,
  `ribbon_renderer.ts`, `program_registry.ts`, `url_state.ts`/`param_codec.ts` (append a param, never
  reorder), tests under `test/`, and your `k1240s4_*` tools. The prototype in
  `.claude/probes/K1240/proto/` is read only: K1290's agent works there in parallel.
- **Commits:** WIP on your branch at each milestone, broken or not. `git add -f` for tools, never for
  outputs. Never push, never edit `LEDGER.md`, never touch the main checkout.
- **Perf lock:** `$env:TEMP\claude-perf.lock`, one line (owner, start time, what). Take it only to time,
  delete it after. While someone else holds it, wait inside one blocking command; a lock older than
  30 min is stale.
- **Stop** when Done holds or 2 h after your start, whichever comes first (`Get-Date` at the start and at
  each milestone). Then commit WIP, append a handoff to this brief and report. Neither a compaction nor
  context size is a stop; after a compaction, re-read this brief and `git log`.
