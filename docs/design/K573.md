# K573 brief: regain G3-1's gap search on the phone

Ledger item K573. K572 (`docs/design/K572.md`, Handoff) found the phone's
render regression: K8 G3-1 (`3465090`, "gap slots reference SAMP with a
chunk-pruned search") made the crossing-gap search cost 57 ms of render
sync on the Pixel 11 (knot gs24), where the old per-slot polyline search
cost 10. The desktop shows +0.6 ms, so it cannot see the problem. The
lore is `.claude/rules/render-gaps.md` ("G3-1: SAMP-referenced gap rows",
and its K572 bullet).

| Phone render sync, median ms | gap on | gap off | the search |
|---|---|---|---|
| knot gs24, `e83f203` (= `3465090^`) | 23.4 | 13.3 | 10.1 |
| knot gs24, `3465090` | 71.6 | 14.1 | 57.4 |
| dense, `e83f203` | 43.8 | 29.0 | 14.8 |
| dense, `3465090` | 68.5 | 27.9 | 40.6 |

What G3-1 changed in the search (`gapNearestFast/Full`, shared by the
section program, its explore variant, the junction fans and the still
pluck): it calls `gapOverPt` twice per segment, each with an int `%`
wrap, float-to-int conversions and a dependent `texelFetch` on `uSamp`,
at 0.09 world spacing (stride at most 3 past 64 points). The old row read
one texel per segment, on segments up to 0.3 long.

## Goal

Bring the phone's gap search back near its pre-G3-1 cost (gate below),
keeping G3-1's data layout and what it was for: SAMP-referenced rows,
chunk pruning, protect ranges, `sure2`, and pruned = brute at 0 px.

## The work, in order

1. **Exact changes first.** Same math, so 0 px against master:
   - Carry the previous segment's end point: one `sampAt` per segment,
     not two.
   - Take the int `%` wrap and the float-to-int conversions out of the
     inner loop (walk an index that wraps once, or split a closed range
     into two straight runs).
   - Reject before any fetch: a fragment outside the slot's bounding
     circle, or outside every chunk circle, leaves before its first
     `sampAt`. The test must be conservative, so no pixel changes.
   - Measure on the phone after each change that could matter, so the
     Handoff can say which one paid.
2. **If the gate is not met, a coarser search walk.** This one changes
   pixels, so prove it is no worse than what shipped before G3-1:
   - For example, a per-slot stride from curvature, or a second, coarser
     SAMP range for the search while drawing keeps 0.09.
   - The search's geometric error must stay within the old polyline's
     (`POLY_SPACING_MAX` 0.3 and `POLY_SAG_TOL`, deleted in `3465090`;
     read them there).
   - Pruned and brute must still match at 0 px (the brute flag walks the
     same points).
   - Show the pixel change on a contact sheet: master vs the fix at
     device scale 1 and 2, with the differing pixels counted.
   - Report the trade in the Handoff. Levi gets the look call if any
     pixel moves.
3. **Verify.**
   - `npm test` and `npm run build`, both green. Update
     `test/render/gap_mask.test.ts` for any layout change, and add a
     test for whatever new invariant the fix relies on.
   - Desktop: a same-state headed A/B of master vs the fix under the
     perf lock. Use the scenes, clock pins and pointer parking from the
     K550 kill's probes (`.claude/probes/K550/kill/` in the main
     checkout, or its worktree's if it is still there): knot, maze,
     thread reveal and burn, at device scale 1 and 2. Pass: 0 px for
     step 1. Step 2 needs its counted change.
   - Phone: the gate, below.
4. **If the time allows,** on the phone at the fix vs master:
   - K568's confetti fall (`.claude/probes/K572/k572_confetti.mjs`);
   - max-fabric's render sync;
   - K147's load fps on the default link.
   K572 did not run these.

## The gate (phone)

- Use `k572_gapoff.mjs`: gap on vs off in one page, `renderLoop(60)`
  render sync. Run it ABBA, fix vs master and fix vs `e83f203`, on knot
  gs24 and dense. Log the skin temperature for every cell.
- Pass: the search (on minus off) comes down from 57 toward 10 ms on knot
  gs24 and from 41 toward 15 on dense, with the off side unchanged (about
  14 and 28).
- If step 1 alone gets within 1.5x of `e83f203`'s search, step 2 is
  optional: report its likely gain and stop.
