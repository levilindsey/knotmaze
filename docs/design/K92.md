# K92: undo and redo for design changes

Levi, 2026-10-13 (`docs/design/levi_notes_2026-10-13.md`): "Let's add
undo/redo buttons above the settings panel, next to the close/open
button. I guess the daily-vs-replay-vs-custom notificaton would then go
below this row. Then we'll need to maintain an undo stack. And handle
auto-toggling enablement/visibility for the undo/redo buttons. The
undo/redo buttons would only be visible when the settings panel is open.
The fog finish indiactor tap decision sgtm."

The point he answered: a tap on the "Free play" badge goes to today's
daily and replaces the link, so a design that was never shared is lost.
Undo brings it back.

## Goal

- **Two buttons, undo and redo,** beside the panel's open/close button.
  - They show only while the panel is open.
  - Each is enabled only when it can act. A disabled button stays
    visible, dimmed.
  - While the panel is open, the mode badge (K73, K151) moves to a row
    below them. Closed, the badge stays where it is today.
- **An undo stack of design changes.**
  - A design change is anything that writes a new design to the page:
    - every panel edit, committed on release as the panel already does
      (`ev.last !== false`), so a slider drag is one entry;
    - a seed change;
    - the Daily button;
    - the "Free play" badge's tap.
  - Every such write goes through `writeParams` in `src/main.ts`, so that
    is the natural place to record the state being left.
  - An entry is the whole state a link carries: the params, plus whether
    a daily is on screen and which one (`dailyN`, `dailyFloating`).
  - Undo restores the previous state exactly as loading its link would.
    The address bar matches, the same maze builds, and a daily resumes
    its saved attempt (K47).
  - Redo walks forward. A new change after an undo clears the redo side.
- **Not in the stack:**
  - maze moves (K80's real time has no move undo: `undoAllowed(clock)`);
  - the camera;
  - anything that is not a design.
- **Your calls, recorded in the handoff:**
  - Do playback preferences (`DAILY_EXEMPT_KEYS`) count as design
    changes? The recommendation is yes, since they are panel edits.
  - The stack's cap. The recommendation is 100.
  - Whether the stack survives a reload. The recommendation is no: it
    lives in memory for the page's life.
  - The browser history. The recommendation is to keep `replaceState`,
    so Back still leaves the page and undo is the buttons' job alone.
- **Out of scope** (file them as ledger items in the report):
  - keyboard shortcuts;
  - K111's Accessibility group;
  - K198's indicator settings.

## What must not change

- Loading a link builds the same maze as before. The K87 pin, the golden
  dailies and the byte-identity golden stay as they are.
- The badge's fit levels (`fit()` in `src/ui/mode_badge.ts`: shorter
  label, one word, the icon, the icon below the menu button) keep
  working with the panel closed, on the desktop and at 411x753.
- The fog's finish-indicator tap only shows a toast (his call (2) on
  K92, which stands).
