## Decisions (approved 2026-10-15)

1. **Reach = `pulseReach`** (pr, default 3, world units of arc from the
   junction; render-paint.md PULSE REACH). One slider: whatever is lit
   is tappable. The runs leaving the junction stay tappable along their
   whole length, as now; the reach decides how far past their far ends
   the taps, the pulses and the hover go. Where a lit run ends inside
   the reach, the light carries on through its far junction and branches
   into every run out of it (not back along itself), until the reach
   runs out. Beyond the first runs, only lit thread is tappable. Keep
   the default 3 and tune it later with Levi.
2. **Movement:** a tap walks the shortest route (walk_graph.ts's
   Dijkstra) to the tapped point, then finishes that run. It moves one
   run at a time, as an arrow-key hold does, and each run is a normal
   move: stats, stars, the fire's clock and the minotaur's turns count it
   as one. A new tap or key replaces the route. Log each run as its own
   tap (`fc.taps`), so saved attempts and replays need no new format.
3. **Visibility:** under the fog or the thread reveal, only shown thread
   is tappable or lit (`shownAt`, `exploreShownAt`).
4. **Stops (turn clock):** the route stops before its next run
   - at a catch, the finish or a loss;
   - under the turn minotaur: when it has just started hunting you
     (spotted you), or when its new telegraph touches the rest of the
     route. Otherwise each run plays as a turn. This is roguelike
     auto-travel: control comes back only when a warning matters;
   - under the burn: before a run the fire would reach before you finish
     it (the run would be smoldering when you get to it; fire.ts `tap()`
     refuses such a run and the page toasts "Smoldering"). The fire is
     deterministic on the turn clock (L = walked distance), so the route
     can be checked when it is planned; stop there with the toast.
5. **Holds get the same stop rule.** An arrow-key or pad hold under the
   turn minotaur today stops only at a catch (gameplay-moves.md); give it
   rule 4 too, so a hold and a multi-run tap behave alike.
6. **Real time** (`clk=realtime` for the minotaur, `fck=realtime` for the
   fire): no warning stops. The route queues run by run and a new tap
   redirects it. A run the controller refuses when it comes up (a
   smoldering arm, tested at its departure clock) ends the route with the
   toast.
7. **No undo question:** there is no move undo (`undoAllowed` in
   minotaur.ts is unused; K92's undo is design-only).

## Stages

- **Stage 1, the game:** routes and stops, without the new light.
  1. A pure route planner (Node-testable): from the head and a tapped
     point (run, position), the run list, the tapped run last; refuse a
     run that is not reachable within the rules.
  2. The move queue in main.ts and the controller: one run per move,
     each a normal move; a new tap or key replaces it; the stop rules 4
     and 6; holds get rule 4 (decision 5).
  3. Taps beyond the first runs: `edgeAt` (or a sibling) accepts a point
     on any shown run within the reach along the walk graph, keeping
     K479's preference among the first runs. The hover glows what a tap
     takes (today's glow on the tapped run is enough in this stage).
  4. Tests: the planner, the stop rules (minotaur hunt start, telegraph
     overlap, smolder, catch, finish), replay determinism (an attempt is
     a tap list; a multi-run tap must replay to the same game), holds.
  5. A probe at the phone viewport and at 1400x900: multi-run taps on a
     few seeds with the turn minotaur, the burn, the fog and the thread
     reveal; report where each route stopped and why.
  6. Lore: a MULTI-RUN TAPS entry in gameplay-moves.md.
- **Stage 2, the light:** the pulses and the hover carry through short
  runs and branch until the reach runs out (decision 1), in the shader and
  its CPU mirror, with the mirror tests (`paint_*.test.ts`) and same-state
  pixel A/Bs (reach 15 and 3, the mode off 0 px where nothing should
  move). The hover lights the whole route a tap would take. Stage 2's
  brief is written when stage 1 hands off.
