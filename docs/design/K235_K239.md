# K235 + K239: no sound in junction cores; a static page's first frame

Two small fixes, mostly in `src/main.ts`. One stage, one agent.

## K235: taps inside junction cores make no sound

Levi, 2026-10-14 about 11:10, on K194's call 5.2 (what should a tap
inside a junction core do?): "I think nothing makes sense. Do we trigger
pluck sounds for this? Probably shouldn't."

Today such a tap (`skipCore`: the tapped span minus the hide zones is
under `LOBE_MIN_LEN`) draws no pluck but plays the pluck sound: 21 of
284 taps on the fabric design in K180's census. See
`.claude/rules/render-pluck.md`, SOUND-ONLY TAPS.

- Goal: a tap that draws no pluck because it falls inside a junction
  core plays no sound either. Every other tap sounds as it does today.
- Find where the tap reaches the synth (`src/main.ts`'s tap path,
  `src/audio/knot_synth.ts`) and where `skipCore` is decided, and gate
  the sound on that same test. If the decision can live in a pure
  function, unit-test it.
- Check whether another sound path reaches a core the same way (a strum,
  a drag across a core, a key move). Report what you find. Change only
  the tap, unless another path is exactly the same case.

## K239: a static page's first frame

K111 found this (`docs/design/K111.md`, "Stage 1 handoff", "A renderer
finding", part 2). A fresh STATIC page (`phy=0&fw=0`, or paused at load)
draws its first frame with the crossing cuts solved at fade 0, about 28k
px off a refreshed frame. In the asleep and paused branches,
`flowRender(force)` calls `renderer.update()` before `fabricTick` hands
the renderer `fadeLength`, `flowStrength` and `flowSpeed`. K111's
`applyAccessibility` already hands the three over itself, for its
toggles.

- Goal: the first frame of a static page equals a refreshed frame (0
  px). Hand the renderer the three values (the worn ones, through
  `look()`) before that `update()`. Prefer one place that hands them
  over for both the load and the toggles to two copies.
- This changes those frames on purpose. Pre-launch that is fine
  (CLAUDE.md, "Pre-launch: no back-compat").
