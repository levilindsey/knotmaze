## K239: a static page's first frame

K111 found this (`docs/design/K111.md`, "Stage 1 handoff", "A renderer
finding", part 2). A fresh STATIC page (`phy=0&fw=0`, or paused at load)
draws its first frame with the crossing cuts solved at fade 0, about 28k
px off a refreshed frame. In the asleep and paused branches,
`flowRender(force)` calls `renderer.update()` before `fabricTick` hands
the renderer `fadeLength`, `flowStrength` and `flowSpeed`. K111's
`applyAccessibility` already hands the three over itself, for its
toggles.

- Goal: the first frame of a static page equals a refreshed frame (0
  px). Hand the renderer the three values (the worn ones, through
  `look()`) before that `update()`. Prefer one place that hands them
  over for both the load and the toggles to two copies.
- This changes those frames on purpose. Pre-launch that is fine
  (CLAUDE.md, "Pre-launch: no back-compat").
