# K794: walked gold stays gold

Ledger: K794. One stage, opus, 2 h cap. Levi, 2026-10-21: "When
retraveling a previously traveled segment, and we render the full path in
yellow, we shouldn't erase the yellow from the segment we're
retravelling."

## The bug

The gold path mode (`pv=gold`, the default) paints the walked path gold.
See `PathViz` and the comment near line 439 of `src/ui/url_state.ts`, and
the mode comment at the top of `src/render/fabric_maze_renderer.ts`. The
gold follows the controller's path stack, so walking back over a run (a
backtrack) pops the run and erases its gold. Levi's ask: once a run is
walked, it stays gold when the player walks it again, in either
direction.

Before changing anything, check on the page which erasures happen. Record
each in the Handoff with a still.
- A backtrack: does the gold recede while the head walks back, and is it
  gone afterwards?
- Walking forward again over a run that was backtracked.
- A loop: walking around a cycle and back onto a run already on the path,
  if the controller trims loops (`fabric_controller.ts`).
- A move over a run that is already gold: does the gold front erase the
  run and regrow it? The front's catch-up is near line 1515 of the
  renderer.

## The fix

These are recommendations. Change one only with a reason in the Handoff.

1. **Paint only.** In gold mode, the gold covers every run walked since
   the gold last cleared, not just the path stack. The controller and its
   path stack, the stats, the stars, the share text and every rule stay
   as they are.
2. **Derive the walked set from the controller's record.** Don't keep a
   new list in the renderer. The controller's `taps` (near line 29 of
   `fabric_controller.ts`: every accepted tap's run, in order) already
   feeds the fog's explored runs (`gameplay-fog.md`, K100 and K174).
   Undo (a replay of the taps minus the last) and a resumed attempt (the
   K47 replay) then come out right with no extra code: Undo takes the gold
   off a run only when no other walk covered it.
3. **The gold clears when it clears today:** a restart, a new maze, or a
   catch or burn that resets the path. If one of those leaves the taps in
   place (a minotaur catch with `minoRefog` off, say), the gold should
   agree with the fog's explored runs. Name that call in the Handoff.
4. **The junction joins.** The route bands (K81: `junction_routes.ts`,
   `render-routes.md`) join the arms a path passes through. With walked
   gold, one junction may join several pairs: each consecutive pair of
   runs in the walk. Where two gold arms meet but no walk turned between
   them, draw what today draws for two gold arms that meet without a
   turn. Check the junction fans (`junction_field.ts`) in a still.
5. **The head and the gold front.** A move along a run that is already
   gold neither erases nor regrows its gold. A move onto a new run grows
   the gold as it does today.
6. **What stays the same.**
   - Trail mode (`pv=trail`) and string mode (`pv=string`).
   - The fog of war, the thread reveal (K76, `xp=`), and the fire's and
     the minotaur's paint, except where they draw the gold.
   - The win. If the solved view draws the player's path, decide whether
     it shows the walk or the route, and say which in the Handoff.
