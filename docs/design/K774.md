# K774: the beat rider's catch never lands

Ledger: K774. One stage, opus, 2 h cap (expect under 1 h).

## The bug

K767's phone sitting found it on the real phone and on the desk. With
the beat rider and the hunter (`clk=beat`, `mt=hunter`), a catch never
lands. The model counts it and respawns both, but nothing follows: no HUD
count, toast, heart or banner. Evidence (read-only; copy what you need
into your own probes folder):
- `C:\Users\lsl\Repositories\knotmaze\.claude\probes\K767\out\catch_desk_sprint\`
- `C:\Users\lsl\Repositories\knotmaze\.claude\probes\K767\notes.md`

The inferred mechanism, not verified: the rider departs on its next run
in the same `advance` as the arrival. `beginMove` then snaps the
animation, so `moveProgress` never reaches 1 and the deferred catch
(`pendingCatch.t = 1`) never lands.

## This stage, in order

1. **Verify the mechanism.** Reproduce it on the page (desktop is enough)
   and in a unit test that drives the beat rider into a catch. Say in the
   Handoff whether the inference held. If it didn't, find the real cause.
2. **Fix it.** Land a pending catch when its animation is snapped or the
   rider departs, unless the root cause points to a better fix. The catch
   lands exactly once: the HUD count, the toast, the heart (lives), and
   the banner when the lives run out. Nothing double-counts.
3. **Check the other paths** for the same pattern: the walker (K114's
   other clock), the sprint (`spr=on`), and lives.
4. **Tests.** Add a regression test for the snapped animation (the
   arrival and the departure in one advance) for the beat rider, and for
   the walker if the pattern applies there.
5. **Page check, desktop.** Play
   `?7&mt=hunter&clk=beat&am=instant&snd=none`, and again with `&spr=on`
   for the sprint path, until a catch lands. Capture the HUD count, the
   toast and the heart. Confirm the classic turn clock still lands its
   catches.
6. **The phone probe.** Copy `beat_phone.mjs` from the main checkout's
   `.claude/probes/K767/` into `.claude/probes/K774/` in your worktree.
   Make its check B require the heart or the toast, so it would have
   caught this bug. Don't run it on the phone.
