## Levi's words (2026-10-13)

> Another possible gameplay mode: You cannot backtrack, segments
> collapse behind you; try to collapse as much of the level as possible
> while still reaching the finish line. Or, alternatively, without
> reaching the finish line

## Decided

- **The param.** `collapse` (off | finish | free), default off. So the
  dailies, the golden pins, K87 and byte identity do not move.
- **The rule.** Collapse rides K137's snap (`fg=snap`,
  `src/game/fragile.ts`): every run you walk collapses behind you.
  A walk is therefore a trail: no run twice. Junctions stay open.
- **The two modes.**
  - finish: collapse as much as you can and still reach the finish.
  - free: the same without the finish. The game ends when you are
    stranded.
- **Par** is the best possible score, found by a depth-first search
  when the maze is built:
  - finish: the longest trail from the start to the finish;
  - free: the longest trail from the start.

  R.3.4's "longest thread" (`docs/design/K80_gameplay_additions.md`,
  about line 1681) is the same measure, used as a finale.
- **The search is deterministic.** One link builds one maze, with one
  par, on every device (K108).
  - Budget the search in steps (nodes expanded), never in wall-clock
    time.
  - When the budget trips, par is the best trail found. The HUD, the
    banner and the share text must not call it the maximum.
- **The search runs only when collapse is on,** and it never changes
  the maze.

## Design (K139 agent, 2026-10-20)

The rules as built (`src/game/collapse.ts`, the controller and main.ts):

- **The limits.** `collapse` != off gives every maze run snap's limit 1
  (K137's `breakLimits`/`isBroken` machinery, so `fragileOn`, the broken
  look, Undo-by-replay and the probes all carry over). Unlike `fg`, the
  END runs collapse too: the start tail on the first move, a stub when
  you enter it (that strands you at its tip), the exit tail when you
  finish. Title runs (K552's prefix before the seam) never collapse and
  score nothing.
- **finish.** Reaching the exit wins, as today. The strand test is
  K137's (no unbroken route to the exit; a BFS route never repeats a run,
  so a route exists exactly when a trail does).
- **free.** The exit is only a dead end: arriving there is not a win. The
  game ends when no unbroken maze run is reachable from the head
  (title runs are walked through), which is also the end after the
  exit tail or a stub.
- **The score** is the share of the maze's thread length collapsed:
  each maze run's length in integer units (`Math.round(length * 1000)`),
  so sums are exact and order-free; shown as a whole percentage, rounded
  down.
- **Par** is the longest trail (in the same units) from the maze's start
  (the seam on a titled maze) over maze runs: to the exit in finish mode,
  ending anywhere in free mode. A depth-first search, children tried
  longest-edge first, pruned by an admissible bound: the length so far,
  plus the unused length reachable from the head, minus half the
  cheapest incident run of every odd-degree vertex there (a trail leaves
  at least one run of each unused, except at its two ends; free mode
  spends the end on the largest term). Finish mode also prunes when the
  exit is out of reach. All integer arithmetic; the budget counts nodes
  expanded. When it trips, par is the best trail found and reads
  `>= N%` (HUD, banner, share), never as the maximum. It runs once per
  maze and mode, only with collapse on, and never touches the maze.
- **Stars** are hidden in collapse games; efficiency is not shown
  either (a long trail is the goal there).

The calls (each built as recommended; alternatives for Levi):

1. **Score: length share** ("as much of the level"). Alternative: runs
   collapsed (simpler to count, but a short stub would count like a long
   loop).
2. **A free game ends when stranded only.** Moves only add to the score,
   so a "done" button has no strategic use; entering a stub or the exit
   tail is the way to stop early. Alternative: a Done action.
3. **Stranded short of the finish (finish mode)** is K137's Stranded
   loss through `rule_loss.ts`, with Undo (replays the taps) and
   Restart. Alternatives: no Undo (a hard mode), or end the game with the
   score and no win.
4. **Collapse overrides `fg` and par (`pa`, `par`)** and brings its own
   par; those rows stay visible but do nothing while collapse is on.
   Alternatives: hide them, or combine (e.g. strokes against the
   collapse par).
5. **With the chase or the fire:** allowed. There is no Undo there, so a
   strand offers Restart only. A catch respawns you at the start, whose
   tail has collapsed, so it strands you at once: in finish mode that is
   the Stranded loss, in free mode the game ends with the score so far.
   Burnt runs block like collapsed ones. Par ignores both. Alternatives:
   forbid the combination, or respawn at the head.
6. **The look: snap's broken run** (the run is gone, with snap's sound
   on each collapse). Alternatives: a collapse fade, dust or burn fronts
   along the run, a crumble sound instead of the snap.
