  frames | looks | cleanup) and parameters: `-Base <ref>` (the round's

  -Ref`, give it a per-run folder parameter (half of K150's fix). Check
  each page's build stamp SHA before measuring it. An A/A pass (one ref

- The frame bench: K81's `gate.mjs` scenarios made generic: knot mode at
  rest (`mf=0`) and fabric mode at 0, 10 and 21 moves, with both builds
  interleaved within each rep. Record fps, p95, the longest frame, the

  K147: a fresh navigation that records rAF intervals for the first 15 s
  (time to first frame, frames over 50 ms, the longest frame, time to
  first sleep), on a default link and on K147's slow case (its
  `LEDGER.md` item: gs 18). Probe links name a design (`?<seed>.J...`):
  a bare URL is today's daily (`.claude/rules/probes.md`).
- Looks as data: a JSON list, where each look has a name, a link, steps
  from a small vocabulary (wait for sleep, wait N ms, tap a target found
  through the page hooks, click an element by text or selector, open the
  panel, scroll) and captures (one shot, or a burst of N at an interval
  for an intro). Shoot each look on both builds and make a side-by-side
  sheet. A look that cannot run on one build (the feature is new) records
  that and goes on. Port K81's `looks.mjs` into this format as the first
  example.
- Output: a `summary.md` in `-Out`, with a table per scenario (base, head,
  the delta, and the A/A noise floor from the smoke test), the sheets'
  paths and the watchdog's verdict, readable without the jsonl.
- Safety, as in the kit:
  - The phone must be awake and unlocked at the start. Never unlock it
    and never wake it with key events: stop and report instead.
  - Never touch Levi's own tabs (K123). Open one tab of your own and
    close only that one, while Chrome is still in front. Leave other
    owners' tunnels and tabs alone: check `adb reverse --list` and the
    DevTools tab list first.
  - The watchdog stops the pass on a touch, any key (power included), a
    lock or another app in front. Retry once, only after 15 minutes
    without touches (`retry_quiet.ps1`).
  - Find the device instead of hard-coding the kit's wireless address:
    `scripts/phone.ps1` handles USB and `-Wireless`.
  - No perf lock: the phone's timings don't depend on the desktop's load.
- Document it in a usage header in the script, and in a short PROBE LORE
  entry in `.claude/rules/probes.md`: the pass, the looks format, and the
  A/A noise floor.

### Design (decided; build this)

Tracked files: `scripts/phone_pass.ps1`, `scripts/phone_pass/` with
`lib.mjs walk.mjs bench.mjs looks.mjs sheet.mjs summary.mjs cleanup.mjs
png.mjs watchdog.ps1 retry_quiet.ps1 looks.example.json noise.json`.
Kit source: `C:\Users\lsl\Repositories\knotmaze\.claude\worktrees\agent-a8c2a999e6c2d5a8e\.claude\probes\K81\phone\`.

- `phone_pass.ps1`: phases `all | start | frames | looks | cleanup |
  summary` (`all` = the five in order; cleanup and summary run even after a
  trip or a failed start). Params `-Base` (required), `-Head` (master),
  `-Looks`, `-Reps` 3, `-Out` (default
  `<repo>\.claude\probes\rounds\<yyyy-MM-dd>-<head short sha>\`), `-Moves`
  "0,10,21", `-LoadSeconds` 15, `-Serial`. It writes `<Out>\config.json`
  (out, adb, serial, hostA/hostB, shaA/shaB, aa, reps, moves, looks file);
  every node script takes that path as argv[2]. State files live in
  `<Out>\state\` (trip, stop, expect.txt, tab id), logs in `<Out>\logs\`.
- `start`, in this order: (1) phone awake and no keyguard, else throw at
  once (never wait, never wake); (2) build each distinct ref once through
  `preview.ps1 -Ref <ref> -Root <Out>\builds -BuildOnly` (an A/A pass
  builds once and serves it on both ports; skip a build that exists);
  (3) two free ports from 5480-5489 (`Get-NetTCPConnection -State Listen`),
  `node node_modules/vite/bin/vite.js preview --outDir <build> --port <p>
  --strictPort --host 127.0.0.1` by absolute path with log files; (4)
  recheck the phone, reverse-tunnel those two ports only; (5) `am start -a
  android.intent.action.VIEW -d "'http://localhost:<B>/?b.J&am=instant&snd=none'"
  com.android.chrome`, then find your tab (retry 40 s) and store its id;
  (6) arm the watchdog, wait 6 s, check the trip file.
- Kit changes (copy, then patch): `lib.mjs` reads everything from
  config.json (no K81 constants, no DRY branch): `tripped()` reads
  `<out>/state/watchdog.trip`; MY_PAGE = URL starts with hostA or hostB;
  `checkBuild` compares the stamp's SHA by prefix (strip a "+"); `rafWindow`
  also reports `over50`. `walk.mjs` = `k81phone.mjs`, with `routedList`
  falling back to every record when `fp.routes` is not a function (master
  has none, so master-only passes would crop nothing). `watchdog.ps1`:
  `-Out`; trip/stop/events files in `<Out>\state`; the kill pattern is node
  processes whose command line contains `$Out` (start node with the config
  path as an argument); keep the touchscreen+buttons filter. `retry_quiet.ps1`:
  `-Out` plus the pass's parameters, runs `phone_pass.ps1 -Phase all` once.
  `cleanup.mjs` = `cleanup_origins.mjs` for the two hosts; cleanup then
  closes your tab by id, removes only your tunnels, stops the watchdog and
  the servers on your ports.
- `bench.mjs` (K81's `gate.mjs`, generic): per rep, both builds
  interleaved (order swaps each rep); fabric 0/10/21 moves (the walk may
  stop early on a short maze: row records `made`), knot `mf=0`; per sample
  fps, p50, p95, longest frame, render ms (`renderLoop`), asleep, thermal.
  Load scenario (K147): `page.evaluateOnNewDocument` installs a rAF
  recorder (`performance.now()` per callback, so t=0 is the navigation);
  time to first frame = the first callback after a `<canvas>` exists; poll
  the stamp every 500 ms for "asleep" for `LoadSeconds`; report frames,
  intervals over 50 ms, longest, p95, ttff, first-sleep time; links
  `?b.J&snd=none` and `?b.J&gs=18&snd=none`, both builds interleaved.
- `looks.mjs` + `sheet.mjs`: the JSON is `{looks:[{name, link, needs?:[hook
  or "param:<key>"], steps:[...]}]}`. Steps: `waitSleep{ms}`, `wait{ms}`,
  `moves{n}`, `tapChoice` (taps the cheapest `choices[].screen`),
  `click{text|selector}`, `panel{open}`, `scroll{to:selector|y}`, `pin`
  (K83's `pinAll`), `shot{name, clip?, junctions?:N}`,
  `burst{name, n, everyMs}`. A look runs on the head build first (junction
  boxes are chosen there and reused on base), then base; a missing hook,
  element or `needs` records `status:"missing"` plus the reason and goes
  on; only a watchdog trip stops the run. Sheet: base on the left, head on
  the right, a colored bar over each column, tall frames area-averaged to
  at most 520 px high, junction crops unscaled, pairs wrapped at 3200 px;
  pixel diff only for single shots of equal size. Port K81's `looks.mjs`
  into `looks.example.json` (frozen link, `moves` 10 and 21, `pin`,
  `shot{junctions:5}`).
- `summary.mjs`: `summary.md` with a table per scenario (base, head, delta,
  A/A noise, verdict), the load table, each look's status, the sheet paths,
  the watchdog verdict and the thermal start/end. An A/A pass also writes
  `<Out>\noise.json` (|head - base| per cell/moves/metric); copy the first
  one to the tracked `scripts/phone_pass/noise.json`, which every later
  summary reads (`-Noise` overrides).
- Also: usage header in `phone_pass.ps1`, and a PROBE LORE entry in
  `.claude/rules/probes.md` (the pass, the looks format, the noise floor).
