## Steps

1. **Baseline.**
   - Build a deterministic catch by runs: a link plus a tap sequence. Use
     the headless `TurnMinotaur` to find one for each `contact()` case in
     the design's table:
     - the same vertex;
     - a head-on swap;
     - arriving where it stands;
     - a wait its path touches.
   - Replay them in the page. Take stills mid-approach and at the cut, at
     1400x900 and 411x753.
2. **The finder.** Add a pure function in `minotaur_turns.ts` that
   locates the catch `contact()` declared: `{ t, player, mino }`, at the
   earliest t where the thread distance is 0.
   - Both motions are piecewise-linear in t, so solve it exactly, as
     `lengthContactFraction` does.
   - Cover every row of the design's meeting-point table. `contact()`
     does not change.
3. **`turn()`'s catch branch, by runs.**
   - Before the respawn, store `lastContact` from the finder.
   - Keep `lastPath` and the route readable until `finishCatchAnim()`.
   - The respawn, the catch count and every later state stay exactly as
     today.
4. **The page.**
   - Rename `pendingTurnCatch` to `pendingCatch` and use it for both turn
     modes.
   - Drop the `byLength` gate from `deferLengthCatch` (rename it), so a
     runs catch defers the same way.
   - `turnCaught(wait, true)` is the shared landing.
   - A wait catch at t of 0 or close to it (refused at `t <= 0.001`
     today) defers with no travel, so it no longer cuts.
   - The toast, the HUD's caught row and the sound move from the tap to
     the contact instant.
   - Input during the travel rides the move's gates, as by-length does.
   - A rebuild mid-travel drops the pending catch (the existing guard).
5. **Tests.**
   - The finder:
     - a head-on swap;
     - a wait touched;
     - arriving where it stands;
     - a two-run overrun past the player's vertex;
     - ending together.
   - Over many seeded games, every catch `contact()` declares by runs
     gets a t in [0, 1] with both spots on the same point.
   - `TURN_GAMES` and `LENGTH_GAMES` hold.
   - A test that names the counted-at-the-tap rule: the catch count is
     already up while the travel plays.
6. **Verify in the page.**
   - The baseline's catches again, same viewports: the dot and the
     minotaur meet on screen before the burst, in every case.
   - A by-length catch looks as it does today.
   - `npm test` and `npm run build` pass, and no pin moves. If one does,
     stop: that kills the approach, not the pin (design, "Kill
     criteria").
7. **Lore.** Correct `gameplay-minotaur.md`'s catch entries where they
   say a runs catch lands at once.
