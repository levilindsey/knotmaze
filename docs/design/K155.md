Neither "careful" model is fit to set T3 yet:
- `careful(H)` is not monotone in H (seed 1: 3.57, 1.93, 2.59).
- `informed(sigma)` is erratic even at sigma 0.1: 1.2x to 27x over seeds
  1-4, and mostly worse than greedy on seeds 1 and 2 (seed 1: 3.2x to 27x
  against greedy's 2.61x). The likely cause (inferred, not tested): it
  weighs retreating (2 x the arrival run + D[v]) against advancing (D[v]
  on the shortest route) with the noise applied to the WHOLE distance. On
  a long maze a 1-2 u run is inside that noise, so it retreats off the
  shortest route,
  and the run it retreated over stays marked used, so it cannot walk it
  again. Fix: apply the noise to the detour (score - D[v]) instead of the
  total, and let a run it retreated over be walked again.

### Proposed design (not built)

- THE MEASURE: R = walked / optimal, where walked is every run walked,
  forward and back. In turn mode walked = path + 2 x backtracked, the
  HUD's own two meters (shown as u x 10 through `fmtDist`). Trail mode
  has no backtracking: path is everything walked, so the same formula
  holds. Stars: one for any finish, two for R <= T2, three for R <= T3.
  A maze with no finite optimal shows no stars. Set T2 near the greedy
  median, so a greedy solve earns two about half the time (K74 measured
  3.12x), and set T3 from the fixed careful player.
- DAILY RECORDS: no new field. DailyResult already stores path, optimal
  and backtrack (`src/game/daily_store.ts`), and dailies are always
  turn-based (`clock` is not a DAILY_EXEMPT_KEY). Old records therefore
  get stars too, and the store needs no version bump.
- REAL TIME: `FabricMazeController.respawn()` empties the path but keeps
  the backtrack meter, so path + 2 x backtracked undercounts after a
  catch. Add a `walkedDist` meter to `src/game/fabric_controller.ts`: it
  adds the run length on every advance and backtrack in `tapEdge`,
  `reset()` zeroes it and `respawn()` keeps it. A catch already costs the
  walk back. On top of that, choose one of two rules: three stars need no
  catch (any catch caps the rating at two), or one star off per catch.
  Decide from the realtime set (K80: the greedy player's median is 0
  catches, 51% of games have none, the mean is 1.26).
- NO PARAM: stars always show, so there is no codec append and nothing
  to renumber against K140.
- WHERE THE STARS SHOW:
  - The win banner (`src/ui/maze_hud.ts`: WinBanner.show and WinInfo,
    with CSS in ensureHudStyles): a stars button under the heading. A tap
    toggles the explanation, and a title attribute covers hover.
  - The History rows of `src/ui/daily_stats_view.ts`, plus an aggregate
    if one reads well.
  - A stars line in `src/game/share_text.ts` (ShareInfo).
  - The main.ts call sites: showFabricWin (around lines 2166-2219), the
    stats view's onShare (around 2331-2344) and the HUD snapshot (around
    1948).
- MODEL AND TESTS: the model goes in `src/game/star_rating.ts`, with tests
  in `test/game/star_rating.test.ts`. They cover each threshold edge, no
  finite optimal, real-time catches and the explanation text, plus the
  share text and stars derived from a stored record.
