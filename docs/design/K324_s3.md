## Steps

1. **The guard on the real-time clock.** It roams within a territory
   around the exit's junction, measured in world units (convert the turn
   guard's territory, and say how). It uses its own sight and accuracy
   (`minoGuardSight`, `minoGuardAccuracy`).
2. **The stalker on the real-time clock.** It hunts whenever you are in
   sight, taking a best step with chance accuracy
   (`minoStalkerAccuracy`). Its charge reads the shared sight, as on the
   turn clock.
3. **Defaults and the panel.** Give real time per-model defaults in
   K294's shape: the same table if the units agree, otherwise a real-time
   one beside it. Show the Behavior row in real time. Move K80's own
   real-time rows (paces, pauses, detect, catch) from the Game folder
   into "Minotaur tuning" (K323 section 3.1; stage 1 left them).
4. **Determinism.**
   - The hunter stays byte-identical: its `K80_DIGESTS` do not move.
   - Add digests for the guard and the stalker.
   - `replayChase` reproduces each model's chases exactly.
   - `plan(reach)` stays true for each model, as stage 1's tests check
     for the hunter.
5. **Tests**, in `test/game/minotaur.test.ts`:
   - a roaming guard never leaves its territory;
   - a stalker hunts once you are in sight, and its steps follow its
     accuracy;
   - each model replays exactly;
   - plus url_codec.test.ts's defaults pin and param_codec.test.ts's
     table pin if you add params.
6. **Sim re-measure** with stage 1's harness. It is untracked in the main
   checkout's `.claude/probes/K324/rt/`; copy it into your worktree.
   - Measure catches per game and % of hunts escaped for each model,
     against the greedy player, the fleer and the queued fleer.
   - Tune the guard's and the stalker's real-time defaults so that each
     reads as its own character and stays fair. Report the table; don't
     chase exact rates.
7. **Page check.** Run a 60 s real-time chase per model, adapting stage
   1's `k324_page.mjs`. Check no page errors, stops held, and plans
   valid.
8. **Lore and the design.** Update `gameplay-minotaur.md` and
   `gameplay-panel.md`. Two stale passages:
   - `gameplay-minotaur.md`'s TURN-ALIGNED MINOTAUR entry (about line
     185) still says `minotaur` = off (default) and turn clock only. Since
     35f3ec2 (K534) the default has been hunter, and `gameMode` decides
     whether a minotaur plays.
   - The design's sections 2.3 and 3.3 say pick on arrival leaves the
     rng draws unchanged. It does not: a pick that a spot or a catch then
     throws away has still used a draw (stage 1's deviation 3; replays
     stay exact).
