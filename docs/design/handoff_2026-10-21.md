## 6. How work runs here

**Agents and sessions**
- If Paseo drives this Muse session from the phone, spawn no subagents
  and run no workflows. A subagent spawn kills Paseo's muse provider
  until a daemon restart (CC59; claude-config
  `incidents/2026-10-14-paseo-muse-subagent-provider-kill.md`, and the
  recovery in `docs/paseo-desktop-handoff.md` section 2). Subagents in a
  local Muse session are fine.
- Ledger owner lines read `muse <session-id>`; an agent's line names the
  agent and its coordinating session.
- Subagents do not edit ledgers. They end their reports with a
  `Ledger items` list, and the coordinator files it.
- An agent works in a worktree on its own branch. It commits WIP at every
  milestone, the first within about 20 minutes, and never pushes. Probes
  go in the main checkout's `.claude/probes/<ID>/`, never a temp
  directory. A worktree with no commits can vanish, and its work with
  it.
- One stage per brief, with a wall-clock cap (two hours for a builder).
  At the cap: commit WIP, append a Handoff to the brief, report.
- `tools/agent_watch.mjs` reads only Claude transcripts. For Muse
  agents, watch their branches' commits instead.
- At most three code agents at once, on different files. A param stage
  touches the hotspot files (`url_state.ts`'s `PARAM_DEFAULTS`,
  `param_codec.ts`, `tweakpane_panel.ts`, `main.ts`), so run param stages
  one at a time.

**The ledger**
- `node C:\Users\lsl\Repositories\claude-config\tools\ledger.mjs <add|move|done|drop|handle|show|lint> --repo C:\Users\lsl\Repositories\knotmaze`
  (flags are in its header; `--dry-run` shows the diff). The next free
  ID is on line 22 (K812 after this hand-off).
- File an item the moment work is deferred, proposed or left over, and
  close it with its commit. Keep In progress handles current.

**Code**
- Commit straight to `master`, end-to-end working, after `npm test` and
  `npm run build`. A red suite fails the deploy and leaves the old one
  live.
- A global hook re-dates work-hours commits to the evening. Take SHAs
  from `git rev-parse HEAD`, not from `git commit`'s output.
- The link codec (`src/ui/param_codec.ts`): append new params; a
  reorder, removal or type change bumps `CODEC_VERSION`. The pins are
  change detectors: `test/ui/param_codec.test.ts`, the golden dailies in
  `test/ui/daily_link.test.ts`, and K87's
  `test/core/maze_plan_identity.test.ts`. Re-freeze what a change moves
  and name it in the commit; pre-launch there is no back-compat.
- Knot mode is guarded byte-identical by
  `test/physics/byte_identity.test.ts`.
- On `fabric_maze_renderer.ts`, `ribbon_renderer.ts` and `main.ts`, grep
  first, then read ranges.
- Never run `wrangler pages project create` or any other wrangler
  scaffolding in this repo.
