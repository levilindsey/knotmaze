# K558 brief: text crossings follow pen order (the later stroke on top), with a reverse switch

Ledger item K558. Levi, 2026-10-19, on the Daily #8 title: "it's
important that the orientation of the crossing (which thread is over
which) be such that, if drawn in actual cursive with a single stroke
from start to end, every later piece of thread goes over the earlier
piece. Add a checkbox parameter for reversing this though."

Context: K115's glyph redesign (stage 8 runs in parallel as research

## Where things stand (master 71ee949)

- **Text over/under comes from `assignOverUnder`**
  (`src/core/text_graph.ts:2263-2419`).
  - It is a parity union-find over the runs between JUNCTION and END
    stops (k = a crossing's index in its run). It makes passes
    alternate where it can, and counts the conflicts. The digit 6 has
    one (`docs/design/K115_stage3.md` 376-381).
  - It sets `node.overFirst` (true when the first pass in strand order
    is over) and a derived `node.isOver` (the slash class of the over
    pass's first lattice segment).
  - `buildTextGraph` (:709) calls it last (:1409). The emblems call it
    too (`src/core/emblem_graph.ts`), and keep it.
- **Its consumers:**
  - Physics `assignCrossings` honors `overFirst` first
    (`src/physics/particle_system.ts:1273-1306`, line 1290).
  - The renderer takes over/under from `ps.crossings`
    (`src/render/ribbon/joinery.ts:730-766`, the `visit(cr.over, true)`
    loop), so it follows the physics.
  - `checkAlternation` (`src/core/tangle_graph.ts:120`) reads
    `overFirst` when it is defined (163-168). It runs at
    `src/core/scene_graph.ts:77, 90 and 199`, and a failure warns
    "Knot invariants violated; generation bug."
  - `src/render/debug_renderer.ts:67, 88` read `node.isOver` alone
    (the debug colors and the slash glyph).
  - Grep `isOver` for the rest: `src/geometry/bend_radius.ts`,
    `joinery.ts`, `types.ts`.
- **Same-slash crossings** (both passes in one diagonal class) can be
  expressed only through `overFirst`. This is K555's item 4.

## What pen order means (picked)

- **Every emitted piece of text has a pen time:** when a writer's pen
  reaches it.
  - The word's connected body is written in one stroke: the main
    strand from its start (`mentr_a` for a title), in its traversal
    order.
  - Every other strand is drawn after the pen lifts: t-bars, i and j
    dots, accents, the strokes of `#`, and any other strand that is not
    the main one. They follow the body in left-to-right order of their
    glyph, ties broken by the glyph's own stroke order (Call C1).
  - With today's builder, a spur or retrace branch (from `dropRetraces`
    or `openCusps`) takes the pen time of the moment the pen leaves its
    junction. The redesign removes these.
  - Find the exact emission order in the code, and document the rule in
    a comment above the new function.
- **At each text crossing, the pass with the later pen time is over.**
  With the reverse switch on, the earlier one is.
  - When both passes lie on the main strand (a loop), the second visit
    is the later one: the loop's up-pass goes under, its down-pass
    over.
- **Equal pen times are a builder bug** (two overlapping pieces). Fail
  loudly in tests; never guess.

## Mechanism (picked)

- **Carry pen time from the builder's input.**
  - Each `SegIn` (the segments `buildPlanar` takes, `text_graph.ts:89`)
    carries a pen-time key: a monotone value along the stroke, e.g.
    stroke ordinal plus arc length, or one global float.
  - The key survives `buildPlanar`'s splitting into fEdges: each piece
    inherits its segment's key, interpolated.
  - At a crossing node, compare the keys of its two passes.
  - The redesign reuses exactly this: it replaces the glyph source and
    keeps "emit `SegIn` with pen keys". Say so in the code comment.
- **Replace `assignOverUnder` for TEXT** with the pen-order assignment.
  - It sets `overFirst` from pen times in strand order, and `isOver` is
    derived as today.
  - The emblems keep `assignOverUnder`, byte for byte. Pin each
    emblem's over/under before and after.
- **Pass the reverse switch down.** `attachTitle`, `attachCartouche`
  and the standalone `text` scene (`?txt=`) all pass it to
  `buildTextGraph` through `opts`. Over/under is set on the word's
  nodes before they merge into the maze graph.
- **Alternation.**
  - Text crossings do not alternate in general: a t-bar goes over its
    stem, and a loop's first pass along the same strand goes under.
  - Exempt text crossings from `checkAlternation` with one typed marker
    (`src/core/types.ts`; your choice of form). The warning then stays
    meaningful for the maze and the emblems.
  - Today's digit-6 warning was parity's, not pen order's; it goes.
  - Physics and the renderer need no alternation, because the word is
    pinned (Decision 1, `docs/design/K115_cursive_text.md`).
- **`debug_renderer.ts`:** derive the over/under it shows from
  `overFirst` (or from `ps.crossings`) instead of `isOver`.

## The param (picked)

- **One boolean, default `false`** (false = the later stroke on top).
  - APPEND it to `PARAM_DEFAULTS` (`src/ui/url_state.ts`) and
    `CODEC_PARAMS` (`src/ui/param_codec.ts:69`; last entry `text`, at
    :309). No `CODEC_VERSION` bump.
  - K552 appends its title flag in parallel. At the merge the
    coordinator puts yours AFTER K552's and re-freezes the table pins,
    so write your tests so that the order is the only conflict.
  - Pick an unused short override key.
- **Daily-exempt** (`DAILY_EXEMPT_KEYS`, `src/ui/daily_link.ts:138-199`;
  Call C2). Over/under never changes a walk graph; it changes the look,
  like the other playback preferences.
- **It crosses the worker seam.** As a `SceneParams` field it goes into
  `SCENE_FIELDS` (`src/physics/physics_worker_core.ts:205-207`) and into
  whatever `sameSceneParams` compares (`src/physics/worker_host.ts`), so
  main and the worker build the same graph. The guards are
  `test/physics/host_seam.test.ts` and `physics_host.test.ts`.
- **Panel:** a checkbox by the text and cartouche rows.
  - Label in 23 characters or fewer, e.g. "Earlier stroke on top".
  - Tooltip, e.g. "Cursive crossings: each later stroke passes over the
    earlier ones, as a pen draws. Check to reverse."
  - A toggle rebuilds the scene.

## Kill criteria

- **A crossing whose two passes have equal pen times:** report the case
  and the builder path that made it. Do not tie-break silently.
- **A titled daily fails the sleep battery** with pen-order over/under
  (non-alternating text weaves have never run): investigate before
  shipping. The word is pinned, so it should not happen.
- **The renderer draws a text crossing opposite to the graph's
  over/under** in any shot: stop and attribute it. The chain is graph,
  then `overFirst`, then `ps.crossings`, then the joinery.
