# K75 brief: yellow banding in recentPath's incoming pulses

Levi, 2026-10-12: "with recentPath [pv=trail], for the current junction
incoming-segment highlight, the pulses of the animation show some
unexpected yellow banding with the highlight pulses."

## Context

- Gameplay paint is per pixel since G2.3 (72041df..a001b34).
- Read `.claude/rules/render.md` (SHADER PAINT; blend COMPOSED colors,
  never palette coordinates).
- Read `docs/design/G2_shader_paint.md`: 3.6 (composition), 3.8 item 11
  (the trail fade went linear in G2), and section 7 (G2.3).
- The code: `src/render/paint_glsl.ts`, `paint_math.ts` (the CPU mirror)
  and `paint_model.ts`; the paint declaration is in
  `fabric_maze_renderer.ts`.

## Method

1. Reproduce on a frozen state.
   - Load `?b.c&pv=trail&trl=5&am=instant&snd=none` and make several
     moves with real clicks (`.claude/probes/probe_winbanner.mjs`).
   - Pin `renderer.paintClock`, park the pointer, and crop the head
     junction's arrival run across a crest phase series.
   - Compare with `pv=gold`, and with pre-G2 master (`e235127`, via
     `scripts/preview.ps1`).
2. Attribute before fixing, with per-term debug views and the census
   probes in `.claude/probes/K4/`. Candidates:
   - a crest composed against the gold trail ramp in coordinate space;
   - the trail-fade window overlapping the inbound crests;
   - the arrival run as both the trail tail and the pulse host;
   - gold between crests.

   Check whether the CPU mirror shows it too: if so the model is wrong,
   if not the shader diverges.
3. Fix the shader and the mirror together. The census stays within
   2/255; run same-state A/Bs in trail and gold modes; add a regression
   test.
4. Run tsc, vitest and the build. Time the GPU per program under the
   perf lock if the shader changed.

## Added scope: the pulse reach (Levi, same evening)

"with the incoming/outgoing segment pulse-highlight animation around the
current junction, I want this to no longer extend across the entire
segment length. Instead, it should only extend a set distance away from
the junction along the segment, adjustable with a parameter, and it
should fade-out at the end. Let's add a slider to control how far this
distance is."

- The distance runs along the run from the head junction, in lattice
  units, with a fade-out at the end. One slider sets it; the fade is a
  share or a fixed length. The default should read clearly as limited:
  median runs are about 3.7 lattice units.
- The new param (e.g. `pulseReach`) is APPENDED to the current codec
  table (v4 if K73 has merged, else v3, which v4 inherits), and its
  slider sits next to pulseSpacing. That lifts the src/ui and codec
  constraint below for the param, the slider and the main.ts wiring
  only.
