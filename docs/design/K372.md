# K372: does fabric `?b` sleep again after a drag?

Ledger: K372. Probe only, no app code. Sonnet, 1 h cap.

## Question

K7 stage 4 saw fabric `?b` stay awake for the whole 30 s it watched after
a drag, on both hosts, master included. (`?b` is seed b at today's
defaults, in fabric mode.)

Two questions:
- Does it sleep again, and when?
- If it doesn't sleep within 180 s of sim time, what keeps it awake?

## Steps

1. **Pick the harness that drives a drag and reads sleep fastest.**
   - First choice: the vite-node harness, if it reproduces the browser's
     physics exactly (`physics-kinks.md`, PROBE LORE). It needs no
     browser, adds no GPU load and needs no perf lock.
   - Otherwise reuse the K63 sleep harness (`.claude/probes/K63/`:
     `gesture.ts`, `lib.ts`, `run.ps1`) or the K41 `b` probes.
     `physics-sleep.md` attaches when you read
     `src/physics/sleep_gate.ts`.
2. **Time the sleeps.** Run `?b` and two other seeds, each at
   `am=instant`:
   - wait for the first sleep;
   - drag a thread (K7 stage 4's drag in
     `.claude/probes/K7/stage4/k7_frames.mjs` is 5 s);
   - release, and record the sim time until it sleeps again, up to 180 s
     of sim.

   Repeat with three drag lengths. If a browser is needed, run both hosts
   (`phw=0` and the default worker).
3. **For any run that stays awake, find out:**
   - which term of `sleep_gate.ts` blocks the sleep;
   - which particles move most, and how fast;
   - whether the motion decays, oscillates or holds steady (a pump);
   - whether contacts sit kinetic.

   Compare with knot mode (`mf=0`) on the same seed.
4. **Write `.claude/probes/K372/results.md`.**
   - A table: seed, drag, host, sim time to sleep (or "awake at 180 s"),
     and the blocker.
   - A verdict, one of:
     - fine: it sleeps, just late;
     - a residual worth fixing: name the mechanism and the likely lever;
     - a duplicate of K12 or K30 (shaped mazes and wide threads that
       never stop).
