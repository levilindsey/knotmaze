# K63 brief: a frame-rate-independent sleep gate

## The finding (K46 scans, 2026-10-12)

Every design sleeps at exactly sim 7.0 s (399 of 400 rect runs), so the
gate sets the timing, not the design. The motion itself drops under the
quiet threshold about 0.6 s earlier. The gate counts 45 STILL FRAMES,
and real settles run physics-bound at 5-10 fps, with dt capped at 0.1 s
per frame. So the window is 4.5 sim-s on every real device, desktop
included, and only 0.75 s at 60 fps. A sim-time window of about 0.75 s
would sleep at about 3.3 sim-s on every design: roughly half the settle
time on the phone and the desktop alike. The daily (the front door)
benefits most.

## Task

1. **Read the gate code first** (main.ts sleep gate, physics quiet
   metrics, `ridersPending`, the physics-off hidden settle) and confirm
   the mechanism with the vite-node harness in `.claude/probes/K41/`.
   Work out why sleep lands at exactly 7.0 before changing anything: is
   it 45 frames x 0.1 s after a quiet start at about 2.5 s, or some other
   floor?
2. **Make the window SIM TIME,** not frames. Choose its length from data:
   - the shortest window with no false sleeps across sweeps of seeds and
     shapes;
   - with a margin.

   A false sleep freezes a still-moving knot. Detect it by comparing the
   frozen state with a reference run that keeps stepping: positions,
   crossing gaps, kink eyes, riders.
3. **Keep every other gate condition:** riders, quiet thresholds and the
   temperature rules. The physics-off mode's hidden settle uses the same
   gate; keep its caps.
