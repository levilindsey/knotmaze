## Context
Phones drop a page's graphics (WebGL) context under memory pressure. K456 (bebdaa1, aaab8f2, merged 2026-10-20) makes the page survive it: a loss saves the attempt and the preferences, pauses the game, and shows a full-screen cover in the maze's ink color, so a white canvas never shows and no tap reaches the blind game. When the context returns the cover goes and play continues. Three calls in it went in as recommended:
- **The cover hides everything**, the HUD and the panel included, for the whole loss. Instead: leave them visible (a panel field would still take keys).
- **The message waits 3 s of visible loss.** Then it reads "Graphics paused", a line on what a reload keeps ("Your progress is saved." on a live daily attempt, "Reloading starts this maze over." in free play) and a Reload button. Instead: show it sooner or later.
- **No automatic reload.** Only the Reload button reloads, so a GPU that keeps failing cannot loop the page. Instead: reload by itself after a wait.

## How to check
1. Open the link and make a move or two.
2. Open the browser console (F12) and grab the loss switch, the way the agent's probe did: `e=[...document.querySelectorAll("canvas")].sort((a,b)=>b.width*b.height-a.width*a.height)[0];e=(e.getContext("webgl2")||e.getContext("webgl")).getExtension("WEBGL_lose_context")`
3. Run `e.loseContext()`: the cover shows over the page, panel included, and ignores taps and keys. After about 3 s the message and Reload button appear.
4. Run `e.restoreContext()`: the cover goes and play continues where it was.
